# **Model Training Mode using the Testbed**

This section guides you through setting up and running your testbed in **Model Training Mode**. The primary goal of this mode is to train your machine learning models using the datasets generated in the "Dataset Generation Mode."  

*Note: In this mode, only the ml\_trainer service is primarily active, leveraging your GPU (if configured). The Wazuh stack and other application core components are **not** started.*

## **Configuration Steps**

The ml\_trainer service is designed to execute your training script. Ensure your training logic is correctly implemented and configured (See more about the training framework [here](training_framework.md)).

* **Training Script:**  
  * **File:** `./training/main.py`.  
  * This is where your actual data loading, preprocessing, model definition, training loop, and model saving logic should reside.  
* Input and Output Paths:  
  The ml\_trainer service uses environment variables and mounted volumes to access data and save models.  
  * **Input Data:** The raw logs generated by coraza-proxy in Dataset Generation Mode are stored on your host at `./training/training-data/raw`. This directory is mounted into the ml\_trainer container at `/app/training/training-data`. Your training script should read data from this path or from the cleaned dataset directly.   
  * **Output Model:** Your trained model will be saved from inside the container to `./ai-microservice/trained-models` on your host.  
  * **Evaluation Logs:** Your trained model evaluation logs will be saved from inside the container to `./training/model-logs` on your host.  
 

* GPU Configuration:  
  The ml\_trainer service is configured in `docker-compose.yml` to request GPU resources.
  ```yml  
  deploy:  
    resources:  
      reservations:  
        devices:  
          - driver: nvidia  
            count: all # Use all available GPUs  
            capabilities: [gpu]
  ```

  * **Prerequisites:** Ensure your host system meets the GPU prerequisites as outlined in the main `README.md` (NVIDIA drivers, NVIDIA Container Toolkit correctly installed and configured for Docker).  
  * **No GPU:** If you do not have an NVIDIA GPU, or if it's not correctly configured, the ml\_trainer container might fail to start with a "could not select device driver "nvidia"" error. In such cases, you will need to:  
    * **Remove the entire deploy section** from the ml\_trainer service in your docker-compose.yml.  
    * **Consider using a CPU-only base image** in `./training/Dockerfile` (e.g., FROM python:3.9-slim-buster) and adjust `requirements.txt` to remove GPU-specific libraries (torch+cu121, tensorflow if you want a minimal CPU-only setup).

## **Running the Testbed for Model Training**

To start the ml\_trainer service for model training, use the following Docker Compose command:  

`docker compose --profile train up --build`

This command will:

* Build (if necessary) and start only the ml\_trainer container.  
* The container will execute the CMD defined in its Dockerfile (e.g., python3 main.py), running your training script.  
* The ml\_trainer container is designed to run its training task and then exit automatically once the script completes.

## **Monitoring Training Progress and Logs**

Since the ml\_trainer container is designed to exit upon completion, it's important to know how to view its output and diagnose any issues.

* View Logs After Exit:  
  After running the up command, the container will likely exit. You can retrieve its full logs using:  

  `docker logs ml_trainer`

* Live Stream Logs (during execution):  
  If you want to watch the logs as the training progresses, run the up command without the \-d (detach) flag:  

  `docker compose --profile train up --build`

  The output will stream directly to your terminal. Press Ctrl+C to stop following the logs (this will also stop the container if it's still running).  
* Keep Container Running for Interactive Debugging (Temporary):  
  For in-depth debugging, you can temporarily modify the ml\_trainer service in `docker-compose.yml` to keep it running indefinitely:  
  ```yml
    ml_trainer:  
      # ... existing configuration ...  
      command: ["tail", "-f", "/dev/null"] # Add this line temporarily
  ```

  Then run `docker compose --profile train up --build -d`. Once the container is running in the background, you can get a shell inside it:  
  
  `docker exec -it ml_trainer /bin/bash`

  From within the container's shell, you can manually run your training script (python3 main.py) and inspect files. Remember to **remove this command override** when you're done debugging.

## **Stopping the Training**

The ml\_trainer container is designed to exit automatically once your main.py (or train\_model.py) script finishes execution.  
If you need to manually stop the training process while it's running:  

`docker compose --profile train down`

This command will gracefully stop and remove the ml\_trainer container, leaving your generated model (if any was saved) in the  `./training/trained_models` directory on your host.
